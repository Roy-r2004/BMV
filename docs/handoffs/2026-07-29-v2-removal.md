## Two fixes that made v1 work again — neither caused by the removal

### 1. `extract_build_errors` discarded every rolldown diagnostic

`app/application/preview_app/build.py` filtered the build log **line by line** on
`error`/`failed`/`cannot`/`unexpected`/`✗`. Rolldown puts the message and the
`file:line:col` **inside a box-drawing block** matching none of those keywords, so
a JSX error reached the fix agent as:

```
✗ Build failed in 312ms
error during build:
Build failed with 1 error:
    at aggregateBindingErrorsIntoJsError (…/rolldown/dist/…)
  errors: [Getter/Setter]
```

No file, no line, no message — request 34 burned all 6 fix attempts on a one-line
error it was never shown. (`aggregateBindingErrorsIntoJsError` survived the filter
because "Error" is *in the function name*.)

Now strips ANSI, keeps a context window after each match, and drops stack frames.
Output went from 1,364 chars of noise to **323 chars, all signal**. Affects
**8 call sites** — the build loop, chat rebuild, and 3 CLI repair scripts.
Covered by 7 tests in `backend/tests/preview_app/test_build_error_extraction.py`
using request 34's verbatim log as a fixture.

Note: request 36 never needed the fix loop, so this fix is verified by its unit
tests, not by an end-to-end repair.

### 2. `PREVIEW_APP_MODEL` had drifted

Request 22 ran codegen on `google/gemini-2.5-flash` (5 calls, avg 25.6 s, all
clean). `backend/.env` had drifted to `deepseek/deepseek-v4-pro`, which truncated
a page, scaffold-fell-back on a *public* page, and held one codegen worker open
**past 10 minutes**. After alignment: **10 pages in 25 seconds**.

Two things make this nasty:

- **Failure is silent.** A truncated slot fill *keeps the scaffold* rather than
  erroring, so a slow model ships lower-fidelity pages with no error.
- **The 120 s timeout bounds nothing.** It is a `requests` *read* timeout, so it
  only trips on inactivity between bytes. A provider trickling output holds a
  worker indefinitely.

Also fixed the surrounding contradiction: `DEPLOY.md` was instructing operators
to set `V2_CANDIDATE_COMPONENT_MODEL` / `V2_CANDIDATE_PAGE_MODEL` — **settings
that no longer exist** — and three files defaulted to `deepseek-chat` while the
docs beside them warned it fails preflight. All now default to
`google/gemini-2.5-flash`. See `docs/ENVIRONMENT.md` → "Which models the preview
generator needs".

## Open items — owner decisions, nothing blocked

1. **Slot-fill accepts syntactically-invalid JSX.** The acceptance check is only
   `"export default" in filled and not looks_truncated_source(filled)`, so
   malformed-but-complete output passes. This produced request 34's broken
   `owner/LoginPage.tsx`. A syntax check would catch it pre-build, but that
   changes codegen's acceptance contract.
2. **AppSpec authoring is fragile.** Two different shadow-pass failures across two
   runs: `call_budget_exhausted` (req 34) and `coverage_review_malformed`
   (req 36). `APPSPEC_MAX_CALLS=6` is tight for `MAX_REPAIR_ATTEMPTS=3` +
   schema repair + coverage — but **raising the budget alone would not have
   prevented the second failure.** Non-fatal only because `APPSPEC_MODE=shadow`.
3. **`fallback_pages` misreports in shadow mode.** In
   `preview_app/pipeline/finalize.py` (~L137-150) the branch that *clears* a
   catalogue scaffold is gated on `ctx.enforce_app_spec`, so with enforcement off
   **every** scaffold is recorded regardless of quality. req 36 reported 8
   fallback pages; running `page_hooks_present` directly showed **all 8 carry
   full AppSpec hooks → 0 would fail enforcement** (req 22 had 6 such pages, and
   shipped the same deterministic `GalleryPage` and the same 739-byte admin
   stub). Fix: measure regardless of enforcement, and let `enforce_app_spec` gate
   only the *failure*. This matters because `fallback_pages` is the metric the
   previous handoff used to judge quality.
4. **31 empty v2 tables.** 33 of 70 tables are v2-shaped, **28 completely
   empty**; only `candidate_artifacts` / `candidate_revisions` are load-bearing
   (for the `rollout` package that was kept). Dropping the rest needs migration
   work gated by the startup schema check (`phase7a`–`phase7f` + `commercial`).
5. **`APPSPEC_V2_COVERAGE_MODEL`** is a live, functional v1 setting with a v2
   name. Renaming means touching env files and compose; left alone deliberately.

## Environment gotchas that cost time

- **`pytest` is not in `backend/requirements.txt`.** Install it per run, and note
  that recreating the container loses it:
  ```bash
  docker compose exec api sh -c 'pip install -q pytest && cd /app/backend && python -m pytest tests/ -q'
  ```
  To run the suite with `docs/` visible (the compose file mounts only
  `./backend`, so one test skips without it):
  ```bash
  docker run --rm -v "$PWD:/repo" -w /repo/backend --entrypoint sh bmv-local-api \
    -c 'pip install -q pytest; python -m pytest tests/ -q'
  ```
- **`docker compose restart` does NOT re-read `env_file`.** Use
  `docker compose up -d api`. `docker compose config` will show the new value
  while the running container still has the old one — verify with
  `docker compose exec api env | grep KEY`.
- **`POST /api/requests` is multipart `Form(...)`, not JSON.** Use `-F`, and note
  the trailing slash 307-redirects and drops the body.
- **Local DB is Postgres, not SQLite.** `sum(bool)` fails; use
  `count(*) FILTER (WHERE ...)`.
- **Session module path** is `app.infrastructure.db.session`, and scripts need
  `PYTHONPATH=/app/backend`.
- **`tests/appspec/` cannot always be collected as a whole directory** — importing
  `app.domain.appspec.validation` before `app.application.appspec` triggers a
  circular import. Naming individual files works.
- **Containers were removed externally once** mid-session (`docker ps -a` empty,
  daemon alive), killing a verification run. Volumes survived intact.
- **`backend/.env` has an appended last-wins override block** pinning the three
  codegen models. Originals are intact above it. Backups:
  `backend/.env.pre-v2-e2e.bak`, `backend/.env.pre-model-align.bak`.

## A correction to `trio-162-164.md`

That file says *"All three runs of the 162-164 trio shipped generic content for
this one reason."* **That is wrong, and the method was the reason.** The check
read a 900-character window of the first catalogue-shaped array and concluded the
model's catalogue was absent. Read properly:

    162  18 titles — scaffold only, and the model's own output was thin (3,311 tok)
    163  30 titles — 'Concrete Mixer 110v', 'Air Compressor (50L)' — real, AND the import
    164  42 titles — 'Adventure Tourer XT', 'Carbon Trail Hardtail' — real

**Only 163 hit the import and only 163 went nuclear.** The plumbing `services`
array sits *alongside* the model's catalogue rather than replacing it, which is
why a marker-based check reported "generic" for apps that were not. The import
fix was still correct — it killed a run outright — but "all three, one reason"
overstated it by two runs.

The lesson is the same one this session keeps producing: **count the thing, do
not sample a window of it.** The corrected check is
`docs/evidence/session28/` → `check.py`'s shape: count distinct titles and look
for plumbing markers separately, because both can be true at once.

## The finding: the content was written, then thrown away

Every shipped app in this trio carries the Brand-default wellness seed —
*"AI-guided consult"*, *"Member aftercare"*, *"Follow-up visit"* — on a bakery, a
hardware store and a bike shop. The seed telemetry says `usable` on all three.
Both are true, and the reason is one line:

    src/data/mock.ts:1   import { Role } from './types';

The prompt's first rule is **"Plain data module — NO imports"**, and
`_valid_synthesized_mock_source` checked three exotic shapes of import — dynamic
`import(`, aliased `import x =`, URL specifiers — while waving through the
ordinary one. So:

1. the model wrote a real catalogue **and** an import of a file that does not exist;
2. the validator accepted it and it was written to disk;
3. `vite` failed — `Could not resolve './types'`;
4. the repair ladder failed with it;
5. `build_phase`'s **nuclear stabilizer** stubbed every route and rewrote
   `mock.ts` with the plumbing mock, discarding the model's catalogue;
6. the plumbing mock is the Brand-default seed, so 162 was then withheld by the
   gate for *its own* placeholders, and 163 died inside the stub writer.

**One defect, and it produced all three outcomes.** It also explains the shape of
the whole session: the "seed dies → generic content" story was right about the
consequence and incomplete about the cause. Before tonight the seed usually never
answered; tonight it answered and was discarded.

## Four fixes, all pre-existing, all `cff858e`

| | what |
|---|---|
| **the import** | Bare `import` is rejected outright — the caller falls to the next model in the chain, which is what the failover is for. Re-exports too, by a source-line regex rather than a token rule: `{ from: '2026-01-01', to: '2026-01-31' }` is ordinary seed data and a token rule cannot tell a date range from a re-export |
| **the variant** | `MarketingHero` has an explicit `variant === 'item'` branch at line 96 and `registry.ts` denied it, so the validator rejected a page the template renders fine. Registry and generated `catalogue.json` now agree, pinned by a test that reads the component's own type union |
| **the stub** | `write_safe_stub`'s docstring promises it "can never fail to build". It could: the catalogue branch validated against the raw error list while `blocking_contract_errors` — which exists for exactly this and already names `invalid variant:` cosmetic — was ignored at that one call site. 163 died at 88 % on a cosmetic mismatch |
| **the placeholders** | `ensure_seed_scaffold_fields` wrote `'Everyday essential'` and `'Guest favorite'` into `seed.items` — the exact strings `placeholder_content_shipped` fails a run for. **The pipeline manufactured the content its own gate rejects**, and 162 was withheld at 574 s for it. It now borrows up to three titles from the catalogue the app already has, escaped, and falls back to brand-derived titles rather than known-failing ones |

8 mutations, 0 survivors. Suite **2,290 passed / 1 skipped**.

## What is still unproven

like.

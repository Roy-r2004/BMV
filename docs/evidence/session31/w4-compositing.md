# W4 — deterministic glamour, and the deck it produces

*Built and rendered 2026-08-11. $0 marginal cost; the one paid run in this
document ($0.22) exists so the committed sample is genuine pipeline output
rather than a reconstruction.*

## The split

The image model renders UI truth — flat, straight-on, edge to edge, which
is what it is good at. Python renders everything around it: browser chrome,
rounded corners, a soft shadow, a brand-tinted backdrop, detail crops. The
model is never asked for a device mockup or a perspective shot, because
doing so garbles the interface text it just got right, and that text is the
product.

`app/pipeline/compositing.py` (`composite-v1`) turns one screenshot into:

| file | what it is |
|---|---|
| `<slug>_0.png` | the raw screenshot, unchanged, corner-watermarked as before |
| `<slug>_hero.png` | chrome + shadow + backdrop — the deck artifact |
| `<slug>_detail_1.png` | the metric band, right of the sidebar, no chrome |
| `<slug>_detail_2.png` | the main content block, no chrome |

Composited from the **raw** bytes, with the BMV mark placed on the backdrop
instead of over the interface. Each file carries a mark, so the "no
unbranded bytes under `/uploads`" policy still holds for every one of them,
and no file carries two.

## What looking at it changed

The deck was rendered through Keynote and inspected slide by slide, which
is the only way these defects surface — this repo has shipped pptx
distortion and overlap bugs twice (`dd181b8`, `d6e8959`).

| seen | fixed |
|---|---|
| composites floating as small pictures in white slides | backdrop margin 9% → 5%; the composite sits inside a slide that already has margins |
| detail crops looked like smaller copies of the hero | crops now start right of the sidebar — a metric band and a content block, not a shrunken screen |
| a browser title bar on top of a crop taken from mid-screen | crops composite with `chrome=False`; the chrome claims something untrue about a crop |
| screenshot cover-cropped into a tall box on employee slides, showing a vertical slice | composites are placed with `contain`; cropping a composite cuts off the frame the compositor just drew |
| a lone caption beside a small image, bottom half of the slide empty | image enlarged and top-aligned, caption under it, prepared-for line at the foot |

And one the **tests** caught rather than the eye: tightening the backdrop
margin pushed the composited logo back over the window's bottom-right
corner — the exact defect this design exists to avoid. The mark is now
sized and placed from the margin band itself, so it cannot re-enter the
interface however the margins change. Pinned pixel-by-pixel
(`test_the_logo_goes_on_the_backdrop_not_over_the_interface`).

## The deck

`docs/evidence/session31/deck/dental-sample-deck.pptx`, rendered to
`slide-001.png` … `slide-004.png`.

1. **Title** — today vs. with the concept (unchanged).
2. **One slide per product screen** (new): hero composite left, the two

conditioned on the pro anchor, and visibly the same product — same

holding up in the artifact a client would actually see.

## Reproducing

```
python scripts/deck_sample.py --brief dental \
    --run-dir scripts/out/bakeoff/dental/google_gemini-3-pro-image__final --request 17
osascript -e 'tell application "Keynote" ...'   # export slide images
```

`scripts/deck_sample.py` needs no DB and no generation — it reads a run
directory, so looking at the deck after a change costs nothing.

## Limits

- Crops are geometric, not semantic. Nothing here knows which pixels hold
  the chart; a layout that puts its chart bottom-right will get a crop of
  something else. Asking a model where to crop would spend money to make a
  deterministic step unreliable.
- The chrome bar is deliberately generic — no tab, no URL text. A
  convincing replica of a specific browser invites the eye to check it.
- Rendered through Keynote, not PowerPoint. PowerPoint's AppleScript export
  produced no files; Keynote's did. The deck is a normal pptx either way,
  but the committed renders are Keynote's interpretation of it.
- The backdrop gradient is subtle by design (brand tint → white). On a
  brand color with very low saturation it will read as plain white.

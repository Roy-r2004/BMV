# Trios 8 and 9 — the first simultaneous starts, and the first real contention

Session 26, 2026-08-08. Six runs, **$1.407 total** ($0.234 a run — well under the ~$0.42
the roadmap has been pricing). Balance bracketed either side: 380.153877615 → 381.560541831.

## What was different about these

**Twelve prior runs used a 60 s stagger and recorded `contention: 0.0` every single time**,
so the concurrency half of the ≤ 600 s DoD row had never been tested — the runs simply never
collided. `POST /api/requests` returns immediately and runs the pipeline on a background
thread, so three POSTs fired from three threads land together. **Measured post spread:
0.002 s on both trios.**

Six **new** businesses, deliberately. The database held 131 requests across 16 business
names, **nine of them art galleries**; re-running the archive would have added samples
without adding coverage. These six also count toward the placeholder row's 20-business
denominator.

## 1. The clock — the row clears, and this time it means something

**Five of five timed runs under 600 s: 570, 556, 577, 564, 553.** Across two trios, which
satisfies the row's own "call it met when a trio clears it twice" rule.

**And contention was non-zero for the first time in the project's history** — 5.7, 17.8 and
5.4 s of `screenshot_session` lock wait. The simultaneous start did what twelve staggered
runs could not. Request 148 is the interesting one: **17.8 s blocked on the lock and still
finished at 577 s**, 23 s inside the cap.

`npm_install` contention stayed 0.0 on all six (warm cache), as on every previous trio.

## 2. 1.11 closes with zero new code

Session 26 re-scoped 1.11 from *"bound the reserve"* to *"prove the reserve holds under real
concurrency"*, on the evidence that the serial tail is 18.1 s mean against a 60 s reserve
and 98 % non-AI. The proof this trio was supposed to produce:

- Worst lock wait: **17.8 s**, against `RESERVE_SECONDS = 60`.
- Worst wall clock: **577 s**, against a 600 s cap.
- The lock-**wait** bound that survived the reverted first attempt still **never fired**, and
  now we know why in a stronger sense: contention exists and is comfortably inside it.

**The reserve holds under real contention.** No code was written, which was the
recommendation.

## 3. Ship rate 1 of 6 — and *which* one shipped is the finding

**Request 151, Vantage Freight Desk, shipped `ready` with zero gate issues.** That is the
**internal_ops dispatch console** — the product kind the session-15 classifier work made
reachable ("staff-only", "not a public website", "no customer ever" beside ops language).
Before that work, `internal_ops` was close to unreachable in plain English and **0 of 47
stored kind_contexts** were one. Its first live outing ships clean.

**The five public-facing briefs all failed**, on two codes:

| code | runs |
|---|---|
| `journey_dead_link_offpath` | 146, 148 (×3), 150 |
| `listing_not_schedule_rail` | 147, 148, 150 |

Neither is the dead-link class the roadmap repaired deterministically (31 → 0, trio 5 clean)
— `journey_dead_link_offpath` is the journey walk leaving the path, a different code.

**The honest reading: this is the first time the pipeline has been asked for six businesses
it has never seen, and it shipped one.** The archive's ship rate was measured on a corpus
that is 9/16 art galleries. A bakery, a physiotherapy clinic, a bike shop, a recording
studio and a hardware store are not exotic, and five of five failed. That belongs in front
of Phase 3, which is about making outputs *differ* — this says the pipeline is tuned to its
own corpus.

## 4. Request 149 — the R2 early-stop working in production, first time

149 did **not** overrun. It failed at **60 seconds**, honestly, and stored no `preview_app`
at all (which is why a poller watching `elapsed_seconds` waits forever — noted so the next
person does not repeat it):

```
AppSpec repair reproduced its parent's validator error set for request 149 —
failing closed instead of spending further repairs
AppSpec failed (repair_reproduced_parent_errors) and fallback is disabled.
(state_assertion_state_required: A state assertion requires state_id.)
```

That is session 24's `repair_reproduced_parent_errors` early stop — landed offline, never
observed live until now — **doing exactly its job**: it recognised the repair was
reproducing its parent's error set and stopped rather than burning the budget. 60 s and
$0.02 instead of a 500 s death.

The underlying validator error, `state_assertion_state_required`, is the **`state_ids`
backfill** already listed as an open item in the handoff. It now has a live reproduction.

## 5. The p50 floor, read carefully

p50 of the five timed runs is **564 s**, against the ≤ 560 s no-regression floor set this
session. **That is not a regression and must not be recorded as one:** the 558.7 s baseline
came from eight runs that recorded `contention: 0.0` — serial work. These five carried real
lock contention. Concurrency costs 5-18 s, and the floor was set from serial evidence
before any concurrent evidence existed.

**Re-base the floor on this trio** (concurrent, ≤ 600 s, 5 of 5) rather than treating a
serial number as the standard a concurrent run must meet.
